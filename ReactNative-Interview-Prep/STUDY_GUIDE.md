## 🎓 Learning Strategy

### Three-Step Learning Process

**Step 1: Understand** (30 mins)
- Read concepts
- Look at code examples
- Run examples locally
- Take notes on key points

**Step 2: Practice** (60 mins)
- Code along with examples
- Modify code to experiment
- Create your own variations
- Run and debug locally

**Step 3: Consolidate** (30 mins)
- Answer Q&A from memory
- Explain to someone else
- Whiteboard key concepts
- Identify weak areas

### Daily Time Investment

**Minimal (2 hours/day):**
- 45 mins: Read + understand
- 45 mins: Code along
- 30 mins: Q&A + review
- Timeline: 4-6 weeks

**Standard (3 hours/day):**
- 45 mins: Read + understand
- 1 hour: Hands-on coding
- 45 mins: Q&A + mock problems
- Timeline: 4 weeks

**Intensive (5 hours/day):**
- 1 hour: Read + understand
- 1.5 hours: Hands-on coding
- 1 hour: System design practice
- 1 hour: Mock interviews
- 30 mins: Review + consolidate
- Timeline: 2-3 weeks

## 💡 Pro Tips & Hacks

### Reading Code

**Method 1: Passive Reading (❌ Don't do this)**
- Just read code from file
- No active engagement
- Quickly forgotten

**Method 2: Active Reading (✅ Do this)**
- Read code
- Pause and predict output
- Run it to verify
- Modify and experiment
- Explain it out loud

### Memorizing Q&A

**Method 1: Passive Memorization (❌)**
- Read answer multiple times
- Close eyes and try to remember
- Often fails in interview

**Method 2: Active Recall (✅)**
- Read question only
- Try to answer from memory
- Check answer
- If wrong, understand why
- Test again after 1 day

### System Design Practice

**Method 1: Solo Design (❌ Less effective)**
- Design alone
- Write solution
- No feedback

**Method 2: Discussion (✅ Better)**
- Design with friend/voice recorder
- Explain out loud
- Discuss trade-offs
- Record and review

### Performance Optimization

**Method 1: Read & Believe (❌)**
- Read optimization tips
- Assume they help
- No verification

**Method 2: Measure & Verify (✅)**
- Make change
- Measure before/after
- See actual improvement
- Understand why

### Spaced Repetition Schedule

**Day 1:** Learn concept
**Day 2:** Review (30 mins)
**Day 4:** Review (20 mins)
**Day 7:** Review (15 mins)
**Day 14:** Review (10 mins)

### Feynman Technique

1. **Choose a concept** (e.g., FlatList optimization)
2. **Explain it simply** - Like teaching a 5-year-old
3. **Identify gaps** - What you struggled to explain?
4. **Study the gaps** - Go back to source
5. **Simplify** - Can you explain it more simply now?

## ❌ Common Mistakes to Avoid

### 1. Only Reading Code
**Problem:** Passive learning, forget quickly
**Solution:** Code along, modify, run locally

### 2. Memorizing Without Understanding
**Problem:** Can't explain or apply
**Solution:** Focus on understanding first

### 3. Skipping Weak Areas
**Problem:** Gaps in knowledge
**Solution:** Identify and strengthen weak areas

### 4. No Coding Practice
**Problem:** Can't code in interview
**Solution:** Code at least 5 challenges

### 5. Ignoring System Design
**Problem:** Unprepared for design rounds
**Solution:** Do all 6 system design scenarios

### 6. No Mock Interviews
**Problem:** Interview anxiety
**Solution:** Do at least 2-3 mock interviews

### 7. Not Profiling Performance
**Problem:** Don't understand actual impact
**Solution:** Measure before and after

### 8. Ignoring Platform Differences
**Problem:** Miss platform-specific issues
**Solution:** Understand iOS & Android differences
